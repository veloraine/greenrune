# Base Body and Stand-in Character Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build our own slim chibi base body on the KayKit skeleton, matching the benchmark model's proportions and face within ±3%, and make its first character (the stand-in) the player, with a one-hand tool carry and a straight two-handed hoe chop.

**Architecture:**
- **Blender (driven by Python):** headless scripts in `tools/blender/` turn one numbers file into a skeleton, a mesh, face parts and textures, then export one GLB that carries KayKit's actions plus our custom ones.
- **Measurement:** a measuring script checks every build against the benchmark targets and exits non-zero when anything is off, so it acts as the test.
- **Godot:** imports the GLB. Small, focused scripts handle the face sheets, the tool-carry layer and the player swap. Headless check scripts verify feet, carry angle and chop drift.

**Tech Stack:** Blender 4.x Python (`bpy`), Godot 4.7.2 typed GDScript, GLB (glTF 2.0).

**Spec:** [docs/superpowers/specs/2026-10-21-base-body-design.md](../specs/2026-10-21-base-body-design.md). Also read [GLOSSARY.md](../../../GLOSSARY.md) and [ADR 0001](../../adr/0001-base-body-on-stretched-kaykit-skeleton.md).

## Global Constraints

- **Proportions:** every measurement is within ±3% of the benchmark, except the foot row, which is replaced by flat boots of about 0.10 × slim width. Ground to crotch stays 0.33.
- **Height:** about 2.9 world units tall; the head is about 0.95 units.
- **Budget:** at most 10,000 triangles without the outline shells. Textures: body about 512², face and hair about 256².
- **Skeleton:** KayKit Adventurers' 41 joints. Bone names and hierarchy are identical to `assets/characters/kaykit-adventurers/Rogue.glb`, and `handslot.l`/`handslot.r` are kept; Godot imports them as `handslot_l`/`handslot_r`.
- **Benchmark files:** `~/Downloads/sample_3d_model_baseline/` is read and measured only. Never copy, trace or retopologise it, and never use its textures. No benchmark data goes in the repo except our own measured numbers.
- **Blender:** `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python <script> -- <args>`.
- **Godot:** `/Applications/Godot.app/Contents/MacOS/Godot`. Checks run with `--headless --path . --script <script>` and exit 0 on pass, 1 on fail.
- **Godot code:** typed GDScript, Godot 4 APIs only. Confirm every API exists in 4.7.2 before using it. Numbers live in `data/` or the proportions file. Comments only for a short non-obvious why.
- **Don't touch:** `data/camera.tres` (the user's uncommitted edit) and `sandbox/`.
- **Every task ends with:** `/pstack:deslop` on the diff, a fresh independent reviewer, fixes, a commit, and a short test script for the user. Each checkpoint task stops for the user's sign-off before the next task starts.

## Review Focus

1. **Switching the hotbar to seeds or an empty slot.** The tool disappears and the right arm goes back to normal idle and walk; it must not stay frozen in the carry pose. Tested in Task 10.
2. **A swing interrupted by a buffered press, or a swing ending.** The carry layer comes back without a visible pop: influence blends over 0.1 s. Tested in Task 10.
3. **Loading a save made with the Rogue player.** It loads with the stand-in, no errors, the player standing on the ground. Tested in Task 11.
4. **The taller player walking through the house door and moving inside the interior.** No getting stuck, and the camera spring arm doesn't clip the ceiling. Tested in Task 11.
5. **Running at full speed with the hoe.** The hoe stays within 15° of vertical and never enters the leg or body. Tested in Task 10.

## Checkpoint 1 — Grey blockout

### Task 2: Benchmark targets and the proportion checker

**Files:**
- Create: `tools/blender/benchmark_targets.json`, `tools/blender/measure.py`, `tools/blender/check_proportions.py`

**Interfaces:**
- **Produces `benchmark_targets.json`:** `{"tolerance": 0.03, "exempt": ["foot_length", "foot_width"], "targets": {<name>: <float>}}`. Every name is a row of the spec's measurement table, normalised to height 1.0. The names:
  - head: `heads_tall`, `head_height`, `head_width`, `face_width`, `neck_length`;
  - body: `shoulder_width`, `torso_length`, `hip_width`, `leg_length`, `upper_arm`, `forearm`, `hand_length`, `foot_length`, `foot_width`;
  - limb thickness: `upper_arm_thickness`, `forearm_thickness`, `thigh_thickness`, `calf_thickness`;
  - face: `eye_height_from_chin`, `eye_height`, `eye_width`, `eye_gap`, `mouth_height_from_chin`, `mouth_width`, `brow_height_from_chin`.
- **Produces `measure.py`:** `measure(objects: list[bpy.types.Object], armature: bpy.types.Object | None) -> dict[str, float]`, which returns the same keys. Use joints when an armature exists, otherwise geometry, as the earlier scratchpad scripts did.
- **Produces `check_proportions.py`:** a CLI. `-- <path.glb|.gltf|.blend> [--targets <json>]` prints a table (name, value, target, % off) and exits 1 if any non-exempt value is off by more than the tolerance.

- [ ] **Step 1:** Write `benchmark_targets.json` from the spec's measurement table. Face values are ratios exactly as defined in the spec.
- [ ] **Step 2:** Write `measure.py` and `check_proportions.py`.
- [ ] **Step 3:** Run it on the benchmark: `Blender … --python tools/blender/check_proportions.py -- ~/Downloads/sample_3d_model_baseline/scene.gltf`. Expected: every value within 3%, exit 0. This proves the measuring matches the targets.
- [ ] **Step 4:** Run it on `assets/characters/kaykit-adventurers/Rogue.glb`. Expected: exit 1, with `heads_tall` about 2.31 against 3.02 and `leg_length` about 0.17 against 0.33. This proves the checker catches a wrong body.
- [ ] **Step 5:** Close out and commit: `feat(tools): benchmark targets and proportion checker`.

### Task 3: Proportions file and the stretched skeleton

**Files:**
- Create: `tools/blender/base_body_proportions.json`, `tools/blender/build_base_body.py`, `tools/blender/check_skeleton.py`

**Interfaces:**
- **Consumes:** `measure.py` (Task 2).
- **Produces `base_body_proportions.json`:** `{"height_units": 2.9, "proportions": {<same keys as the targets>}, "boots": {"length": 0.10, "width": <slim>}, "chest_shape_key": <float 0..1 default>}`. Values start at the targets.
- **Produces `build_base_body.py`:** a CLI. `-- --out <path.blend> [--stage skeleton|blockout|face|dressed] [--export <path.glb>]`. Each stage includes the ones before it.
- **Produces `check_skeleton.py`:** a CLI. `-- <built.blend|glb>` exits 1 unless:
  - the bone-name set equals Rogue.glb's 41 joints;
  - every bone's parent matches Rogue's;
  - every bone's rest-pose direction (roll and axis) is within 1° of Rogue's.

- [ ] **Step 1:** Write `check_skeleton.py` and run it on Rogue.glb against itself. Expected: exit 0.
- [ ] **Step 2:** Write the skeleton stage of `build_base_body.py`.
  - Import Rogue.glb's armature, delete its meshes and the stray Icosphere, and keep its actions.
  - Lengthen and move bones in edit mode so the joint positions give the proportions × `height_units`, keeping each bone's direction and roll.
  - Scale every action's `hips` location fcurves by (new hip height ÷ Rogue hip height), so KayKit clips keep the feet on the ground.
- [ ] **Step 3:** Run `--stage skeleton`, then `check_skeleton.py` on the output. Expected: exit 0.
- [ ] **Step 4:** Close out and commit: `feat(tools): proportions file and stretched KayKit skeleton`.

### Task 8: Weights, export and the animation fit test

**Files:**
- Modify: `tools/blender/build_base_body.py` (weights; export with KayKit's actions)
- Create: `tools/godot/fit_test.gd`, `docs/superpowers/reports/2026-10-21-fit-test.md` (generated)

**Interfaces:**
- **Produces:**
  - `stand_in.glb` with the skinned mesh and all 76 KayKit actions under their original names;
  - `fit_test.gd`, a CLI: `--headless --script tools/godot/fit_test.gd` writes the report. Exit 1 if any clip in the Phases 1–3 list fails.

- [ ] **Step 1:** Write `fit_test.gd`. For every clip, it samples 30 frames per second and checks three things:
  - **Ground:** the lowest point of either sole relative to the floor. Fail if it sinks more than 2 cm or floats more than 2 cm while that foot is the planted one.
  - **Slide:** for Walking_* and Running_A, how far the planted foot moves against the speed `scripts/player.gd` uses. Fail above 5 cm per step.
  - **Clipping:** hand or forearm through the torso or head, using capsules that approximate the body. Fail above 1 cm of penetration.

  The Phases 1–3 list: Idle, Walking_A, Walking_B, Walking_C, Running_A, Use_Item, 1H_Melee_Attack_Chop, 1H_Melee_Attack_Slice_Horizontal, PickUp, every Sit_* and every Lie_*. Every other clip is reported, never failed.
- [ ] **Step 2:** Add the weights stage to the build: automatic weights, then normalised with at most 4 bones per vertex. Export with actions.
- [ ] **Step 3:** Run `fit_test.gd`. Fix each failing listed clip:
  - adjust weights;
  - or adjust the hips scaling (Task 3);
  - or rebuild the clip in Blender as a corrected copy with the same name.
  Repeat until the run exits 0.
- [ ] **Step 4:** Close out and commit: `feat(character): skinned stand-in with fit-tested KayKit clips`.
